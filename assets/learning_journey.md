# THE LEARNING JOURNEY

### Q1: How did I start learning AI?

**A:**

I started with Python fundamentals, but I realized early that simply reading documentation or watching tutorials wasn't an effective way for me to retain information.

I gradually shifted to a build-first, theory-second approach. I would choose something I wanted to build, identify the concepts I didn't understand, learn those concepts, and then return to the implementation.

This approach helped me connect theoretical knowledge with practical use. It may sometimes feel less structured, but building things is how I retain concepts most effectively.

### Q2: What's my actual methodology when learning something new?

**A:**

My approach is hands-on first. Before going through extensive documentation or tutorials, I try to build a small working version of the concept, even if it breaks.

For example, while learning FastAPI, I started experimenting with path parameters and query parameters instead of reading the entire framework documentation first. When something didn't work, I investigated the error and learned the underlying concept.

I'm currently following this same approach through a six-phase FastAPI curriculum, progressing from foundational concepts to industry-grade patterns. I'm building one continuous project throughout the curriculum rather than solving disconnected exercises.

### Q3: What's my actual learning progression? What did I learn and in what order?

**A:**

My learning progression has been:

1. **Python:** I started by learning Python fundamentals and programming concepts.
2. **Machine Learning:** I moved into Machine Learning and completed approximately 70% of the CampusX 100-Day ML playlist, focusing on understanding the fundamentals.
3. **Generative AI and RAG:** I moved into Generative AI and Retrieval-Augmented Generation (RAG). This was an important stage because I could see how embeddings, retrieval, and LLMs work together in a practical pipeline.
4. **Agentic AI:** I explored LangChain and tool-calling agents, learning how an LLM can interact with tools and external information.
5. **Multi-agent systems:** I moved towards LangGraph to understand stateful workflows and multi-agent coordination. I'm currently learning it by building the MSME Underwriting Agent rather than relying only on courses.
6. **Backend development:** I'm also developing my backend skills through FastAPI, following a structured six-phase learning curriculum.

### Q4: What's my honest skill level right now?

**A:**

I'll be direct about my current abilities because I believe understanding my gaps is important for improving.

- **Python:** I understand the concepts, but I still find it challenging to write complete solutions independently from a blank file. I'm currently stronger at reading, understanding, and modifying existing code than generating everything from scratch.
- **DSA:** This is currently one of my weakest areas. I'm at an early stage and actively rebuilding my fundamentals.
- **LangChain:** I can read and understand LangChain code comfortably, but writing implementations independently without references is still developing.
- **RAG and Generative AI:** I've implemented these concepts in my Digital Twin project, which is a live, working agentic RAG system.
- **LangGraph:** I'm actively learning it through the MSME Underwriting Agent project, especially multi-agent coordination and state management.
- **FastAPI:** I'm learning through hands-on implementation. My current level is still early, and I'm progressing through a structured curriculum.

The biggest gap I recognize is the difference between understanding how something works conceptually and being able to implement it cleanly from scratch, especially under pressure. I'm actively working to close that gap.

### Q5: Why do I prefer building projects instead of only taking courses?

**A:**

I prefer building projects because courses often demonstrate the expected or successful path, while real understanding develops when I encounter and solve problems myself.

My Digital Twin project taught me a lot through actual implementation challenges, including ghost data bugs, hallucination issues, and a difficult Streamlit Cloud deployment involving multiple cascading errors.

Similarly, the MSME Underwriting Agent is helping me understand multi-agent systems practically. I understood the importance of state handoffs more clearly when I had to design them myself and encountered problems caused by incorrectly structured handoffs between agents.

These experiences have helped me understand not only how technologies work, but also why certain implementation decisions matter.

### Q7: What's my overall philosophy about learning AI and technology?

**A:**

My learning philosophy is based on building practical things while being transparent about what I understand and what I still need to improve.

I don't want to claim mastery of a concept just because I've completed a tutorial or can explain its definition. I want to understand how it works, implement it, encounter real problems, and learn how to solve them.

I'd rather honestly say that I don't fully understand a particular concept yet and explain how I'm working on it than pretend I have mastered it.

For me, continuous improvement starts with recognizing knowledge gaps and consistently working to close them.
